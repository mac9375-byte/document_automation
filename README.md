# 검사성적서 관리 시스템

출하검사 **기준서(Word)** 를 읽어 **검사성적서(Excel)** 를 만들고, 그 과정과 결과를 **이력으로 관리**한다.

> 한국성전 AX컨설팅 과제 No.6 「출하검사 성적서 작성 자동화」(품질팀) 구현.
> 과제 원안의 요구 — 모델별 검사항목·규격 백데이터화 / 성적서 양식 자동 반영 /
> 검사 항목 수에 따른 시트 자동 구성 — 을 모두 충족한다.

---

## 1. 실행

```bash
python run.py
```

브라우저에서 `http://127.0.0.1:8000` 접속. 사내망의 다른 PC는 이 PC의 IP로 접속한다.

| 옵션 | 설명 |
|---|---|
| `python run.py --local` | 이 PC에서만 접속 |
| `python run.py --port 9000` | 포트 변경 |

설치는 필요 없다. 다른 PC로 옮길 때만 `pip install -r requirements.txt`.

---

## 2. 운영 흐름

```
개발부서 의뢰
      │
      ▼
① 모델 등록 ──▶ ② 기준서(Word) 업로드 ──▶ ③ 열 매핑 확인 ──▶ ④ 검사항목 적용
                                                                      │
                     ⑥ Excel 성적서 출력 ◀── ⑤ 성적서 작성·측정값 입력 ◀┘
                                              (자동 판정)
```

모든 단계가 **변경 이력**에 남는다 (누가 · 언제 · 무엇을).

### ② 기준서 업로드

모델 화면에서 `.docx` 기준서를 올린다. 시스템이 문서 안의 표를 모두 찾아
검사항목 표를 추정하고, 문서번호·REV·모델명·품번·SEC CODE를 본문에서 추출한다.
**원본 파일은 개정 이력으로 보관**되며, 같은 파일을 다시 올리면 해시로 동일본임을 알려 준다.

### ③ 열 매핑 확인

열 역할(구분 / 검사항목 / 규격 / 단위 / 검사방법 / 측정기구 / 시료수)을 자동 추정해
드롭다운에 채워 둔다. 기준서 양식이 모델·작성자마다 조금씩 달라
**최종 확정은 담당자가 화면에서 한다**. 원문 표 미리보기와 추출 결과를 나란히 보여 준다.

구분 열이 세로병합(vMerge)으로 비어 있으면 위 값을 이어서 채운다.

### ④ 검사항목 적용

적용하면 해당 기준서가 그 모델의 **현행** 기준서가 되고, 이후 만드는 성적서에 근거로 기록된다.

규격 표기는 자동으로 하한·상한으로 변환된다.

| 기준서 표기 | 하한 | 상한 |
|---|---|---|
| `25.40±0.20` | 25.2 | 25.6 |
| `0.50+0.05/-0.03` | 0.47 | 0.55 |
| `1.0~2.0` | 1.0 | 2.0 |
| `MAX 50`, `0.10 이하`, `≤3.5` | – | 50 / 0.1 / 3.5 |
| `MIN 1.0`, `100 이상`, `≥0.8` | 1.0 / 100 / 0.8 | – |
| `이상 없음` 등 수치 아님 | OX 판정으로 처리 | |

### ⑤ 성적서 작성

성적서를 만들면 그 시점의 검사항목이 **스냅샷으로 복사**된다.
나중에 기준서가 개정되어 마스터 규격이 바뀌어도 **이미 발행된 성적서는 변하지 않는다**.

측정값을 넣으면 상·하한과 비교해 항목별 OK/NG와 종합판정(합격 / 불합격 / 판정보류)을 자동 계산한다.
자동판정이 불가능한 항목은 **수동지정**으로 담당자가 직접 넣는다.

### ⑥ Excel 출력

| 시트 | 내용 |
|---|---|
| `성적서` | 머리정보 + 구분별 항목수·OK·NG 요약 |
| `외관` `치수` `기능` `도금` `추가` | 구분별 검사항목·규격·측정값·판정 (항목 있는 구분만) |
| `이력` | 이 성적서의 작성 이력 |

한 구분의 항목이 30건을 넘으면 `치수(1)`, `치수(2)` 로 시트를 자동 분할한다
(`report_excel.ROWS_PER_SHEET`에서 조정).

## 3. 이력관리

| 화면 | 내용 |
|---|---|
| **기준서 이력** | 업로드한 기준서 원본, 문서번호·REV, 적용 항목 수, 현행본 표시 |
| **변경 이력** | 모델·기준서·검사항목·성적서에 일어난 모든 변경 (모델/대상별 필터) |
| 모델 상세 | 그 모델의 기준서 개정 이력 + 최근 변경 이력 |
| 성적서 상세 | 근거 기준서 링크 + 그 성적서의 이력 |

기록되는 행위: 생성 · 수정 · 삭제 · 업로드 · 일괄적용 · 판정 · 상태변경 · Excel출력

담당자 이름은 화면 우측 상단에 한 번 입력해 두면 이후 모든 이력에 기록된다.

### 삭제 보호 (품질기록 보존)

- 성적서가 있는 **모델**은 삭제되지 않는다
- 근거로 쓰인 **기준서**는 삭제되지 않는다
- **승인** 상태의 성적서는 삭제되지 않는다

## 5. 설계 결정

- **스냅샷** — 성적서는 작성 시점의 검사항목을 복사해 둔다. 품질기록이 소급 변경되면 안 된다.
- **열 매핑은 사람이 확정** — 기준서 양식 편차가 커서 완전 자동 매핑은 오판 위험이 있다.
  자동 추정으로 작업량을 줄이되 확정은 담당자가 한다.
- **의존성 최소화** — `fastapi` / `uvicorn` / `openpyxl` / `python-multipart` 네 개뿐이다.
  DB는 `sqlite3`, Word 파싱은 `zipfile` + `xml.etree`, CSV는 `csv` — 모두 표준 라이브러리다.
  `python-docx` 를 쓰지 않는 이유는 .docx 표 구조(`w:tbl`/`w:tr`/`w:tc`)가 표준으로 고정되어
  표준 라이브러리로 충분하기 때문이다.
- **인증 없음** — 사내망 전용 도구이고, 이력에 '누가'를 남기는 것이 목적이다.
  사내 SSO나 ERP 계정을 붙일 때는 `app.actor_of()` 하나만 교체하면 된다.

## 6. 아직 안 된 것

| 항목 | 상태 |
|---|---|
| **기존 사내 성적서 양식 그대로 출력** | 원본 `.xlsx` 양식 파일을 받지 못해 표준 레이아웃으로 생성한다. 원본을 주면 `report_excel.build_report_workbook()` 만 교체하면 된다. |
| **ERP 검사실적 연동** | 과제 진척표의 미해결 요청사항. 현재는 측정값을 화면에서 입력한다. 검사기 로그(과제 No.3·4·10)와 데이터 형식을 맞춰야 한다. |
| **기준서 도면(WA) 치수 추출** | 과제 No.5(기준서 자동화)가 DXF로 처리 중. 이 시스템은 기준서의 **표**만 읽는다. |
| **사용자 인증·권한** | 위 '설계 결정' 참고. |
| **구형 `.doc`** | Word에서 `.docx`로 저장해야 한다. |
